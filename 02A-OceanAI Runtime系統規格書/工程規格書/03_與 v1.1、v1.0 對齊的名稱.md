## 2.1 Names aligned to v1.1 and v1.0｜與 v1.1、v1.0 對齊的名稱

**EN**  
In architecture specification v1.1 §6.5, ORT is the system-level runtime architecture. ORT Cloud Runtime is its cloud-side runtime implementation. ART is its local runtime implementation on an Artibird Hub. In this specification, Cloud Runtime Service is ORT Cloud Runtime, and Hub / ArtiOS Runtime is ART. They are two implementations with their own codebases. They follow the same scene execution logic and serve different scopes. ORT Cloud Runtime serves all managed schools and homes. ART serves the one school or home assigned to that Hub.

Engineering specification v1.0 §6.7.1 names the command entries. When the App is on the campus LAN and can reach the Hub, the command follows the ART Local Path. Otherwise it follows the ORT Cloud Path. Device feedback is received by the Hub first, then reported to the cloud. The Hub and the cloud each publish feedback to the App, and the App filters the duplicate notice. This naming does not adopt D01, and it is not evidence that the two codebases have been compared.

**ZH-TW**  
架構規格書 v1.1 第 6.5 節裡，ORT 是系統級運行架構。ORT Cloud Runtime 是其雲端 Runtime 實現。ART 是其本地 Runtime 實現，部署在 Artibird Hub 上。本規格的 Cloud Runtime Service 即 ORT Cloud Runtime，Hub／ArtiOS Runtime 即 ART。兩者各有一套程式碼，遵循相同的場景運行邏輯，服務範圍不同。ORT Cloud Runtime 服務所有已納管的學校與家庭。ART 服務該 Hub 所屬的一所學校或一個家庭。

工程規格書 v1.0 第 6.7.1 節寫明命令入口。App 在校園區域網路內且能連通 Hub 時，命令走 ART 本地控制路徑。其餘情況走 ORT 雲端控制路徑。終端回饋先由 Hub 接收，再上報雲端。Hub 與雲端各自向 App 發布回饋，由 App 過濾重複訊息。此名稱對齊不採用 D01，也不作為兩套程式碼已經對照過的證據。
